# Editor worklist — 0.1.12, preparing for the restructuring

**Status:** NOT STARTED. Everything here is **minor or patch**, so none of it
waits for 0.2.0 and none of it presumes the final hierarchy. See ROADMAP §S for
the measurements behind it and §S5 for why these two levels are separable from
the reparenting.

**How to use this.** Every "current" string below is quoted **verbatim from
`vocab/pkm-vocab.ttl`**. Every "proposed" string is a *proposal* — accept,
rewrite or reject each one. The edits happen in the SKOS Editor, from the real
project (CONTRIBUTING §Releasing step 3); I verify the export afterwards with
`compare_exports.py`, where the expectation for this release is that
`definition` and `scopeNote` **will** differ, because it is a prose release.

Grouped by concept so each term is opened once.

## Part A — mint (minor, additive)

Only terms whose absence is independent of whatever shape the hierarchy takes.
Adding `skos:hasTopConcept` for a new concept is additive too, so any of these
can be a top concept immediately without demoting anything.

### 1. `Personal Knowledge Management`

The subject of the namespace, absent from all 223 concepts (§S1).

- `skos:prefLabel` — **proposed:** `Personal Knowledge Management`
- `skos:altLabel` — **proposed:** `PKM`
  (this is what makes the phrase findable in search; today `pkm` matches only
  the eleven `PKM *` implementation terms)
- `skos:definition` — **proposed:** "The practice of capturing, organizing,
  connecting and retrieving what one person knows, so that it stays usable over
  time."
- `skos:scopeNote` — **proposed:** "The practice, independent of any tool. A
  system that implements it is a PKM System; the tools it is implemented with
  are Technology."

### 2. `Technology`

Named by Doug as a top concept; absent (§Q4). Five of the current eight top
concepts are technology of one sort or another, and this is the term they are
instances or kinds of.

- `skos:definition` — **proposed:** "A tool, platform, language, service or
  protocol used to build or run a system, as distinct from the concepts the
  system organizes."
- `skos:scopeNote` — **proposed:** "Technology-specific terms belong here rather
  than under the concepts they implement, so the generic vocabulary stays
  readable by someone using different tools."

### Open question, not a proposal

**Is `PKM System` distinct from `Personal Knowledge Management`?** Doug has
named both. The defensible split is practice versus implementation — PKM is what
you do, a PKM System is a particular arrangement that does it, and Knowledge
System Architecture is *his* PKM System. If that split holds, `PKM System` is a
third mint; if not, KSA narrows from `Personal Knowledge Management` directly.
Worth deciding before minting, because it changes what KSA's parent is.

Already banked elsewhere, not restated here: §K's interface kinds (`API`,
`REST`, `GraphQL`, `MCP`, `Command`), §P's Capacities primitives (`Tag`,
`Object`, `Property`, `Relationship`), and §E's `Collection` and `Vocabulary`.

## Part B — adjust prose (patch)

Each of these is wrong or vague under *any* hierarchy, so none of it is wasted
work if the shape changes.

### 3. `pkmv:EffortsFolder` — a folder defined as a thing

`skos:definition`

- **current:** "A unit of directed work toward an outcome, such as a project or
  initiative."
- **problem:** that is the definition of an *Effort*, not of a folder. The only
  folder concept in the vocabulary whose definition describes a thing rather
  than a place (§S3).
- **proposed:** "A major space within an Obsidian vault containing notes about
  action (\"what you do\"), holding efforts such as areas, interests and
  projects."
- **why this wording:** it copies `AtlasFolder`'s definition shape — "A major
  space within an Obsidian vault containing notes about knowledge (\"what you
  know\")" — so the three ACE spaces finally read as parallel.

### 4. `pkmv:Action` — enumerates its own siblings, and cites a phantom

`skos:definition`

- **current:** "Something to do for an effort, project, area, or interest."
- **problem:** names Area, Interest and Project, which are its three siblings
  under `EffortsFolder`. Defining a term by listing what sits beside it is the
  self-referential shape §C and §H swept elsewhere.
- **proposed:** "A discrete thing to be done, small enough to be completed or
  checked off."

`skos:scopeNote`, first bullet only — leave the other four alone

- **current:** "- Narrower than an Effort, and alongside Area, Interest, or
  Project."
- **problem:** `pkmv:Effort` **does not exist** (§K, §S4). The note promises a
  concept the vocabulary has never had, and `prose.py`'s phantom-citation rule
  cannot see it because `Effort` is one word and the rule needs two CamelCase
  segments.
- **proposed, if `Effort` is minted:** leave as is — the citation becomes true.
- **proposed, if it is not:** "- The smallest unit of work in this system,
  below the efforts it belongs to."
- **note:** this is the one line here whose right answer depends on a decision
  (whether to mint `Effort`, banked in §K), so it may be cleaner to defer this
  bullet to whichever release mints it.

### 5. `pkmv:Time` — defined in terms of the model, not the thing

`skos:definition`

- **current:** "A concept element representing a temporal reference point or
  duration."
- **problem:** "a concept element" describes the vocabulary's own machinery
  rather than time. A reader learns nothing they did not bring.
- **proposed:** "A period or point in time, at any horizon from a day to a
  life."
- **leave the scope note alone.** It already declares the right structure —
  "Treated as the anchor/parent for the Calendar hierarchy (Life > Decade > Year
  > Quarter > Month > Week > Day)" — and it is the graph that contradicts it,
  not the prose. Fixing the graph is Part C.

Already banked elsewhere, not restated: §K's three literals that name FastAPI as
though it were the category (`PKMPythonAPI` definition and scope note,
`PKMPythonServices` scope note).

## Part C — blocked until 0.2.0 (major)

Listed so the worklist is honest about what it is *not* doing. Each changes what
an existing query returns, which [Versioning](../../CHANGELOG.md#versioning)
makes major.

1. **Reparent the six periods** — Day, Week, Month, Quarter, Year, Decade — from
   `Calendar` to `Time`, which `Time`'s own scope note already says is their
   parent (§S2). The single highest-value move in the restructuring.
2. **Move `Action`, `Area`, `Interest`, `Project` off `EffortsFolder`** — these
   are §P2's four `broaderGeneric` links, the ones asserting that a project is a
   *kind of* folder.
3. **Resolve `Calendar` vs `CalendarFolder`** — two concepts for one folder,
   stacked (§S3). Related: §E's four-way `Day` question.
4. **Demote the technology top concepts** — five of the current eight. Note the
   asymmetry: *promoting* the new tier is minor and can happen first, so the
   roof can go on before the walls move.
